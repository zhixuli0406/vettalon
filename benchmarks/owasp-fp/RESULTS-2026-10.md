# OWASP Benchmark 誤報率實驗（2026-10-13）

量化 vettalon 的誤報率，並回答核心問題：**跨家族覆核到底降了多少誤報？**

方法見 [README.md](README.md)。樣本：OWASP BenchmarkJava 的 **160 個 case**（SQLi、命令注入、路徑穿越、XSS 四類，各類 TP/FP 各 20 個；即 80 個真漏洞 + 80 個安全誘餌）。百分比附 95% 信賴區間。每個 case 一次跨家族掃描同時得到「finder 有沒有標」（單模型陽性）與「有沒有存活成 needs_human」（跨家族陽性）。

## 結果一：vettalon（Claude 找洞 + Codex 跨家族覆核）

| 配置 | 召回（TP，n=80） | 誤報率（FP，n=80） |
|---|---|---|
| 單模型 finder（Claude） | 78/80 = 98% [95%CI 91–99%] | 0/80 = 0%（95% 上界 ≤ 3.8%） |
| **＋跨家族覆核** | **73/80 = 91% [95%CI 83–96%]** | **0/80 = 0%（≤ 3.8%）** |

在這個樣本上，Claude 本身就很精準（80 個安全誘餌一個都沒標錯）。所以這裡跨家族覆核的角色是**精準度護欄**——維持 0 誤報，召回小幅降到 91%。

## 結果二：基準直接抓到並修好一個真 bug

第一次跑時，跨家族覆核把召回從 100% 砍到 **66%**（路徑穿越 8 個真漏洞只留 2 個）。查下去發現 verifier 的 prompt 有個過度嚴格的規則：**看不到部署端的認證/暴露脈絡就 refute**，即使程式碼裡「未淨化的攻擊者輸入直流到危險 sink」已經完整可見。

修法是把兩種不確定分清楚：
- **程式碼本身安全**（輸入已淨化/參數化/白名單、sink 不危險、流程已被守衛）→ refute（這是該抓的誤報）。
- **部署脈絡未知**（端點有無認證、怎麼暴露、base 路徑指哪）→ 當 blocker、標 needs_human，不是 refute 的理由。

修完：召回 66% → **94%**（n=32 當時的前後對照；路徑穿越 2/8 → 8/8、命令注入 4/8 → 7/8），precision 不變；擴大到 n=160 後穩定在 91% [83–96%]。這是基準驅動的產品改進，不是為了好看調數字——修的是真實的漏報。

## 結果三：跨家族覆核對「會產生誤報的模型」降了多少誤報

結果一裡 Claude 太精準，看不出跨家族「抓誤報」的價值。所以換一個會產生誤報的較弱 finder——本機的 qwen2.5-coder 7B——再測一次（qwen 找洞、Claude 跨家族覆核）：

| 配置 | 召回（TP，n=80） | 誤報率（FP，n=80） |
|---|---|---|
| qwen 7B 單獨 | 60/80 = 75% [95%CI 65–83%] | **46/80 = 57% [95%CI 47–68%]** |
| **＋跨家族覆核（Claude）** | 51/80 = 64% [95%CI 53–73%] | **0/80 = 0%（≤ 3.8%）** |

| 類別 | qwen 誤報（/20） → 跨家族後 |
|---|---|
| SQLi | 20 → 0 |
| 路徑穿越 | 16 → 0 |
| XSS | 10 → 0 |
| 命令注入 | 0 → 0（qwen 這類沒標） |

**跨家族覆核把 qwen 的誤報率從 57% 砍到 0%，80 個安全誘餌裡它標錯的 46 個全被擋下，同時保住 60 個真發現中的 51 個。** 這是「跨家族覆核降誤報」最乾淨、統計上也站得住的證明（95% 上界 ≤ 3.8%）。

## 適用範圍

這組數字支持：

1. 在 OWASP Benchmark 的 160 個 case 樣本上，vettalon（claude 找洞、codex 覆核）召回 91%（95% CI 83–96%），80 個安全誘餌零誤報（95% 上界 ≤ 3.8%）。
2. 跨家族覆核把 7B 本機模型的誤報率從 57%（95% CI 47–68%）降到 0%（95% 上界 ≤ 3.8%），保住 60 個真發現中的 51 個。用便宜或本機模型找洞時，覆核的效果最明顯。
3. 這套基準抓出並修好了 verifier 過度嚴格的 bug（召回 66%→94%）。

這組數字不代表真實程式碼的表現：OWASP 的 case 是合成的、單檔自足，比真實程式碼簡單。真實整庫召回目前較低（約 5/9，受大檔覆蓋限制，見 [../recall/RESULTS-2026-10.md](../recall/RESULTS-2026-10.md)）。強模型本身就精準，跨家族對它的降誤報效果不明顯，引用時要寫清楚是哪種模型配置。

## 限制

- 樣本 160 個（每格 20 個，TP/FP 各 80）。百分比附 Wilson 95% 信賴區間；零誤報用 rule-of-three 給 95% 上界（≤ 3.8%）。再擴大樣本可再收窄，但趨勢已明確。
- OWASP BenchmarkJava 是 Java 合成測試，不代表真實專案的分佈。
- LLM 有隨機性：單模型 FP 在兩次跑之間在 0–3% 間變動（≤1 case）。報告中以區間標示。
