# Finite input to dynamic evaluation oracle

Contract `finite-input-to-dynamic-evaluation-v1`, schema version 1. This is a finite input-dependency relation over self-authored Python source, not a vulnerability, exploit, reachability, or human-confirmation verdict. Fixtures are never executed. Parsing and compile-only syntax checks do not execute a code object.

`observe(source: bytes) -> dict` (`analyze` is an alias) accepts at most 2 KiB exact UTF-8 bytes and 256 AST nodes. The sole module statement must be `def subject(user_input):` without annotations, decorators, defaults, variadic arguments or other parameters. Supported statements are single-name assignment, return, and a standalone direct `eval(expr)` or `exec(expr)` with one positional argument. Expressions are string constants or previously bound local names/parameter. No fixture import, eval, exec, subprocess, attribute access, branches or arbitrary Python evaluation occurs. Sink return values are deliberately unknown, so a sink used as an assignment/return value is unsupported.

At most one sink is supported. Binding `eval`, `exec`, or rebinding the parameter, repeated local binding, unresolved names and other AST constructs are rejected. Unsupported is never safe. A present but unobserved sink, duplicate sinks or inconsistent identities are incomplete. Inputs are exactly the ordinary strings `11` and `22`; only operand UTF-8 bytes are recorded.

Result keys: `schema_version`, `contract`, `source_sha256`, `status`, `complete`, `relation`, `reason`, `traces`, `sinks`. Status is `complete`, `oracle_unsupported`, or `incomplete`; relation is `input_dependent`, `input_independent`, `no_sink`, or null. Sinks have `opcode`, `operand_literal`, `byte_start`, `byte_end`, `source_sha256`, `sink_bytes_sha256`, `sink_ast_sha256`, `operand_ast_sha256`, `function_binding`, and `binding_lineage`. Ranges are absolute UTF-8 byte offsets, end-exclusive, recomputed against each exact source. Fingerprints use Python AST dump with attributes/locations excluded, SHA-256 over its UTF-8 bytes; their interpretation is tied to the Python AST/runtime used in the experiment.

Each trace contains `input`, `source_sha256`, `opcode`, `byte_start`, `byte_end`, `operand_hex`; absent observations have null opcode/range/operand. `verify_observation(source, trace)` independently recomputes exact finite trace and rejects altered identity, range or operand, including wrong JSON scalar types.

`map_sink(parent_source: bytes, child_source: bytes, origin: dict | None = None)` returns `status` (`mapped` or `minimize_mapping_unknown`), `reason`, `sink_lineage_id`, `origin`, `parent_sink`, and `child_sink`. Both sources must be complete with exactly one sink, identical opcode, full sink/operand AST fingerprints, function/parameter identity and recursively recorded binding lineage, plus unchanged finite relation. Original bytes are retained in `origin.source_hex` and re-parsed/re-hashed on subsequent mapping; origin metadata is never trusted by itself. Origin identity is scoped to this experiment and is not a vulnerability root-cause ID. Different source hashes and ranges remain distinct observations even when lineage maps.

`deletion_candidates(source: bytes) -> list[dict]` proposes only whole-line top-level statement deletions whose re-parsed child still maps uniquely and preserves relation; no query or scanner input is read. Each entry has `source` bytes, `removed_statement`, `parent_source_sha256`, `source_sha256`, and `mapping`. Shared-line statements are not deleted. Candidates do not claim global minimality or scanner mismatch persistence; the controller must separately spend its fixed scanner budget to verify that condition.

The six opaque dev files are fixed before first scan. The literal-eval form includes the irrelevant `note = "context"` assignment, allowing a meaningful deletion if an actual dev mismatch exists. Independent/no-sink labels in the plan are expected hand calculations, not substitutes for executing this oracle. No holdout source or labels are read.
